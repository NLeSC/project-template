# Research Software Directory checklist

Prepare the project for a Research Software Directory entry.

## Metadata

- [ ] Clear software name.
- [ ] Short description for non-specialists.
- [ ] Longer description with scientific context.
- [ ] Repository URL.
- [ ] License.
- [ ] Maintainers and contributors.
- [ ] Organizations and affiliations.
- [ ] Keywords and research domains.
- [ ] Links to documentation, demo, paper, or project page.
- [ ] Citation information and DOI when available.

## Content quality

- [ ] README explains what the software does.
- [ ] README explains who it is for.
- [ ] Installation or usage instructions are present.
- [ ] Screenshots or diagrams are available when useful.
- [ ] Project impact is stated carefully and concretely.
- [ ] Limitations are honest.

## Sustainability

- [ ] Maintenance status is clear.
- [ ] Contribution route is clear.
- [ ] Governance or maintainer information is present.
- [ ] Release and archive process is documented.

## Suggested short description pattern

`TODO software name` helps `TODO audience` to `TODO task` by `TODO technical approach`, supporting `TODO research outcome`.
