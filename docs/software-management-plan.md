# Software Management Plan

A lightweight starter for project teams.

## Purpose

What research question or workflow does this software support?

## Users

Who will use it during the project? Who might use it later?

## Software shape

Package, web app, workflow, notebook, model, API, command-line tool, dataset utility, or other.

## Reuse

What existing tools, libraries, standards, or services will be reused?

## Quality plan

How will the team check correctness, reproducibility, usability, and maintainability?

## Documentation plan

Where will user and developer documentation live?

## Release and citation plan

How will releases, Zenodo archiving, DOI, and citation metadata be handled?

## Maintenance and handover

Who maintains the software after active development? What does a future maintainer need?

## Risks

What could make the software hard to maintain, reuse, or trust?
