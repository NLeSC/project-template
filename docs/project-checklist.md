# Project checklist

## 1. Start-up

- [ ] Define the research question.
- [ ] Define intended users.
- [ ] Define the smallest useful version.
- [ ] Choose the project maturity target.
- [ ] Create repository from this template.
- [ ] Replace all `TODO` placeholders.
- [ ] Add GitHub topics.
- [ ] Add maintainers.
- [ ] Add license and citation metadata.

## 2. Design and architecture

- [ ] Write `docs/architecture.md`.
- [ ] Record major decisions as ADRs.
- [ ] Decide the software shape: package, app, workflow, model, API, dashboard, or other.
- [ ] Identify existing tools to reuse.
- [ ] Identify user workflows.
- [ ] Identify data and privacy constraints.

## 3. Development quality

- [ ] Add tests or validation checks.
- [ ] Add formatting and linting where relevant.
- [ ] Document installation.
- [ ] Document common usage.
- [ ] Document limitations.
- [ ] Add examples or demo data when possible.

## 4. FAIR and open science

- [ ] Apache 2.0 license confirmed.
- [ ] `CITATION.cff` validates.
- [ ] `.zenodo.json` is complete.
- [ ] Zenodo GitHub integration is enabled.
- [ ] DOI badge added after release.
- [ ] RSD entry prepared.
- [ ] Software is findable through topics and metadata.

## 5. Release

- [ ] Version chosen.
- [ ] Changelog updated.
- [ ] Release notes written.
- [ ] Tests pass.
- [ ] Documentation reflects release behavior.
- [ ] GitHub release created.
- [ ] Zenodo archive checked.
- [ ] Citation instructions updated.

## 6. Handover

- [ ] Maintainers listed.
- [ ] Architecture current.
- [ ] Release process current.
- [ ] Known issues triaged.
- [ ] Deployment or operational notes written.
- [ ] New maintainer can run, test, and release the project.
